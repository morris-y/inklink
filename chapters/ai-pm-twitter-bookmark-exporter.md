這篇寫給兩種人：想把推特（X）書籤整批匯出的人，以及跟我一樣、平常說自己是 builder 卻很少真的動手做東西的 PM。

## 為什麼要做：我對 AI 很上頭，但實踐得夠多嗎？

PM 不是一個常常弄髒雙手去 build 的工種。所以 PM 說自己是 builder，有時候其實挺心虛的。每天看著 AI 飛速發展、大家喊 e/acc，自己卻沒做出什麼東西，總覺得有點愧對 Sama、Steve Jobs、Elon Musk 和列祖列宗。

我每個週末都會花點時間推進 idea 清單上的題目。但很多題目太大，常常一停就是好幾個月，卡在調研階段。整個過程缺少回饋，也練不到 PM 真正有價值的幾項技能：**產品發現、需求驗證、交付能力、戰略思考。**

所以那天下午，我照「刻意練習」的原則，找了一個小題目：最好 4–5 個小時做得完，啟動成本越低越好，而且能很快確認有真實需求。

## 產品發現與需求驗證

我的推特書籤積了一大堆沒細看的內容。我偶爾會看，但新增的速度比消化快太多。我想把書籤全部下載下來，交給 AI 分類和摘要。

第一步是把書籤匯出。X 的設定裡有「下載你的資料」，可以拿到你發過、互動過的內容，但書籤是「別人的內容」，不在下載範圍內。我又把 Chrome 線上應用程式商店和 GitHub 上的工具看了一輪，不是收費，就是功能不全。

那就自己爬吧。我在本機寫了一個 Playwright 腳本，很快爬下一批推文。問題是，長推文會被「顯示更多」按鈕截斷，拿不到全文，這不是我要的結果。

做到這裡，我開始覺得這本身就是個不錯的題目：

1. 做出來至少能解決我自己的需求。
2. 越來越多人用 AI + Obsidian 這類個人知識庫管理內容，這個需求可能會越來越大。
3. 商店裡幾個收費的同類擴充功能，底下有 6,000 多則評論。這代表需求一直都在，算是一種側面的市場驗證。

## 交付：從本機腳本到 Chrome 擴充功能

決定動手後，我把工作分成兩個階段。

**第一階段：在本機把流程跑通。** 目標是在保留登入狀態的前提下，分步驟抓到每則推文的完整內容、發文時間和網址。我只需要這三個欄位，用 Playwright 在本機跑就夠了。

本機腳本只能當技術驗證。確認能零成本拿到想要的資料之後，我開始想使用者的流程：一般人不可能在自己電腦上跑 Playwright。既然一定要在瀏覽器上操作，最方便、也已經被商業驗證過的形式，就是 Chrome 擴充功能。

**第二階段：改寫成擴充功能。** 我從來沒寫過擴充功能。只知道以前裝過一些開源擴充功能，要開開發人員模式、把資料夾拖進瀏覽器，裡面有 `manifest.json` 和一些 JS。真的開始寫才發現，直接拖進去載入，也是本機測試最快的做法。

## 戰略思考：小工具也能拿來練商業化

本機版很快就跑通了。接著我開始想：這東西能不能給別人用？初期怎麼給、後期怎麼給？怎麼設計 CTA 讓人願意試用、願意付費？

這當然是一個很單純、天花板很低的小工具，但拿來練商業化思考還是很有用。做產品不外乎三件事：

- **賣什麼**：一個 Chrome 擴充功能，把推特書籤匯出成 CSV，含全文、發文時間和網址。
- **在哪裡賣**：上架 Chrome 線上應用程式商店，瀏覽器工具最自然的通路。
- **怎麼賣**：
  1. 第一次使用時，先讓使用者免費抓前 100 則書籤、下載 CSV，自己檢查欄位夠不夠用。
  2. 滿意的話，轉 USDT 到指定錢包，把交易簽章寄到 email，系統自動回信一組 API key，之後下載次數不限。
